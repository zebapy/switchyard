1 · Scope & behavior

The panel is contextual to the active tab. Each tab is bound to a worktree (a path + branch). When you switch tabs, the panel re-targets that worktree. When the active surface is the dashboard or settings, the panel hides or shows an empty state.

  • Toggle: an icon button in the TabBar right cluster + a keybinding (joins the existing useKeybindings set). Open/collapsed state + width persist in the session, mirroring the left sidebar.
  • Target path: derived from the active tab's worktree (workspace store → active window/tab → pane cwd). All backend calls take this path, exactly like get_git_info(path) / get_pr_info(path) today.
  • Sections (top → bottom): (a) branch + PR header, (b) changed-files list with diff viewer, (c) PR actions, (d) checks/jobs list.

4 · Backend (Rust) work

New #[tauri::command] fns. All commands auto-allowlist once registered in lib.rs (capabilities file needs no per-command entry). Opening URLs already works via the opener plugin.

Git — new file src-tauri/src/git_diff.rs (or extend projects.rs)

CommandSignatureImpl
git_status_files(path) -> Vec<FileStatus>git2 repo.statuses() → per-file {path, index_status, worktree_status, is_staged}. Mirrors git status --porcelain.
git_diff_file(path, file, source) -> FileDiffUnified patch for one file. source ∈ unstaged | staged | vs_base. git2 diff with single-path filter → emit hunks.
git_diff_base_files(path, base?) -> Vec<FileStatus>Files changed vs merge-base(HEAD, base). base auto-detected (main→master→origin/HEAD).
git_default_branch(path) -> StringResolve main vs master vs origin/HEAD symref. Cache per repo.
#[derive(Serialize)]
pub struct FileStatus {
  pub path: String,
  pub status: String,   // "M" | "A" | "D" | "R" | "?" | "C"
  pub staged: bool,
  pub added: i64,
  pub deleted: i64,
}
#[derive(Serialize)]
pub struct FileDiff {
  pub path: String,
  pub hunks: Vec<Hunk>,   // or raw unified text — see Q6
  pub binary: bool,
}

Note: git2's diff line callbacks give origin (+/-/context) + content per line — enough to build a structured hunk model, or just concatenate to a unified-diff string and parse client-side.

6 · Diff viewer design

Two inputs to the same viewer: (a) working-tree changes (unstaged + staged), (b) diff vs the base branch (merge-base of HEAD vs main/master). A segmented control at the top of the changed-files list switches source; clicking a file loads its patch into DiffView.

Rendering options are the main open decision — see Q6. The app already runs lazygit in a pane, so a heavy in-app diff UI may be redundant; a lightweight custom renderer keeps the panel consistent with the existing dark, mono aesthetic and avoids a big dependency.

8 · Checks / jobs drill-in

  • ChecksList renders each CheckRun: status icon + name + duration + "open on GitHub". Grouped by conclusion or listed flat.
  • Drill-in (Q5): simplest = click opens the check's html_url in the browser. Richer = CheckDetail fetches the job log via the Actions API and shows it in a mono scroll view inside the panel (more work: log download endpoint returns a redirect to a zip/stream; needs parsing).
  • Auto-refresh while any run is in_progress (poll ~10s); stop when all settled.

9 · Phasing

Phase 1 — Panel shell + status (git-only, no API blockers)

Right panel slot in App.tsx, ui/workspace state, resizer, toggle + keybinding, persistence. Header showing branch + existing total +/- counts. Empty states. Ships value without touching GitHub.

Phase 2 — Diff viewer

git_status_files + git_diff_file + git_default_branch + git_diff_base_files. ChangedFiles list w/ Unstaged·Staged·vs-main segments. DiffView renders selected file.

Phase 3 — PR status + view + create

Wire GithubSettings into Settings page first. PanelHeader PR badge + View-on-web (reuse get_pr_info). Then github_push_branch + github_create_pr + CreatePrForm. Needs the OAuth blocker resolved.

Phase 4 — Checks list + drill-in

Refactor compute_ci → github_pr_checks (per-run). ChecksList + open-on-web. Optional CheckDetail in-app log viewer. Polling while running.
