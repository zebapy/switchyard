How it works (30-second version)

Push a git tag like app-v0.1.0 → GitHub Actions builds a .dmg for each Mac architecture → creates a draft GitHub Release with the installers + a latest.json manifest. You review and publish. The app reads that latest.json on launch and self-updates.

The updater is signed with a minisign key (the one just generated) — totally separate from Apple code signing. That's why auto-update works even though the app is unsigned.

1 · Add GitHub secrets

Fastest with the gh CLI (keeps the private key out of your clipboard/terminal history):

gh secret set TAURI_SIGNING_PRIVATE_KEY < ~/.tauri/switchyard_updater.key
gh secret set TAURI_SIGNING_PRIVATE_KEY_PASSWORD --body ""

Or in the web UI: repo → Settings → Secrets and variables → Actions → New repository secret. Paste the full contents of the .key file into TAURI_SIGNING_PRIVATE_KEY; leave the password secret empty (the key has no password).

Back up ~/.tauri/switchyard_updater.key somewhere safe (password manager). Lose it and you can never ship an update your installed apps will accept — users would have to reinstall manually.

3 · Wire up the in-app update check

New file src/lib/updater.ts new — no try/catch, errors propagate to your app boundary:

import { check } from "@tauri-apps/plugin-updater";
import { relaunch } from "@tauri-apps/plugin-process";

export async function checkForUpdates() {
  const update = await check();
  if (!update) return;
  // optionally confirm with the user here before installing
  await update.downloadAndInstall();
  await relaunch();
}

Call it once after the app mounts (e.g. in App.tsx inside a useEffect). Add a real "check for updates" confirmation/UI later; this is the minimum.

4 · Cut a release

  • Bump the version in all three: package.json, src-tauri/tauri.conf.json, src-tauri/Cargo.toml (they must match — the updater compares the app's tauri.conf.json version against latest.json).
  • Commit, then tag and push:
git tag app-v0.1.1
git push origin app-v0.1.1
  • Watch the Actions tab — both arch jobs build and attach to one draft release.
  • Open the draft release, sanity-check the .dmg assets + latest.json, then Publish. (Updater ignores drafts — it only sees published, non-prerelease.)
