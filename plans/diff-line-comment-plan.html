Comment on a diff line → send to a new /grill-with-docs chat

Plan for review. Tick the options you want, fill the text boxes, then hit Copy answers at the bottom and paste back to me.

Goal

In a Diff pane, hover a line → click a comment affordance → type a note → it spins up a new agent chat seeded with a /grill-with-docs prompt that references file:line, the line's content, and your comment.

How it would work (UX)

1
Hover any line in the diff. A small Comment button appears at the right edge of that row.
2
Click it → an inline composer opens under the line with a textarea + Send to new chat.
3
On send: open a new Claude agent tab in the project, then type the prompt into it and (optionally) submit.
4
Focus jumps to the new chat. The agent runs /grill-with-docs with the file/line/comment as context.

Technical approach (verified against the code)

Good news — there's already an "initial prompt" channel. addTab(..., {kind:'Agent', command, agent}) passes command straight to the Rust spawn, which launches the agent as {agent} {shell_quote(command)} (pty.rs:254). So we can seed the grill prompt at launch with no pty timing hacks.

  • New chat (preferred): addTab(repo, label, {kind:'Agent', agent:'claude', cwd:repo, command: grillPrompt}) — same path AddMenu.tsx:69 uses, plus the existing command arg.
  • Caveat: this passes the prompt as a launch argument (claude "/grill-with-docs …"). Need to confirm Claude runs a slash command when given as the initial arg. If it doesn't (treats it as plain text), fall back to typing it into the TUI via invoke('pty_write', {id, data}) (the call TerminalPane.tsx uses) once the pane's first output arrives. See D4.
  • Line data: the Diff pane knows the file (paneInfo.diffFile) + source. The line number + content come from the diff2html row (.d2h-code-linenumber text and .d2h-code-line-ctn).

Open risks

  • Boot timing: if we write before claude is ready, input is lost. Mitigation: wait for first output chunk, then write (with a fallback delay). Could still be flaky on slow starts — acceptable for v1?
  • Overlay fragility (if D1=overlay): reading .line-num2/.d2h-code-line-ctn depends on diff2html's DOM staying stable. Pinned by the lib version; low risk.
  • Escaping: your comment + line content are sent as plain typed text into the TUI (not a shell), so no shell-injection surface; bracketed paste keeps it literal.
