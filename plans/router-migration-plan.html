Router migration plan

Switchyard (Tauri + React 19 + Vite + zustand) → React Router v7, memory history

Why a router, and which one

today No router. Navigation is a zustand string union useUiStore.mainView: 'dashboard' | 'pane' | 'settings'. View switches scattered across ~8 files via showPane() / showDashboard() / setSettingsOpen(). Settings sections are scroll-anchors, not routes. Overlays (palette, help, modals) layered separately.

chosen React Router v7 with createMemoryRouter. Desktop app = no URL bar, so memory history (in-memory stack), never BrowserRouter. Gives declarative route→component map, nested routes for settings, an imperative router.navigate() usable outside components (keybindings), and a clean place to persist/restore the active surface.

Scope guard: the router tracks which surface is shown — not pane trees, terminal state, or modal open/close. Those stay in the workspace/ui stores. Overlays remain zustand-driven and render on top of every route.

Route tree

// src/router.tsx
createMemoryRouter([
  {
    element: <RootLayout/>,        // Header + Sidebar + <Outlet/> + global overlays/modals
    children: [
      { index: true, element: <Dashboard/> },              // '/'
      { path: 'work/:tabId?', element: <Workspace/> },      // TabBar + SplitPane
      {
        path: 'settings',
        element: <SettingsLayout/>,                         // section nav + <Outlet/>
        children: [
          { index: true, loader: () => redirect('default-folder') },
          { path: ':section', element: <SettingsSection/> },
        ],
      },
    ],
  },
], { initialEntries: [restoredPathFromSession ?? '/'] });
  • RootLayout = the persistent shell currently inlined in App.tsx (Header, resizable sidebar/ProjectTree, <main> → <Outlet/>) plus all overlays/modals so they exist on every route.
  • Workspace = the mainView === 'pane' branch (TabBar + SplitPane key={activeTab.id}). Active window/tab still come from the workspace store; :tabId is optional sugar for restore/deep-link.
  • Settings nested routes are phase 4 polish — phase 1 can ship /settings as the single existing page.

The imperative-nav trick (why this stays simple)

Many call sites switch views from non-component code: useKeybindings.ts uses useUiStore.getState().showPane(). createMemoryRouter returns a router object with .navigate(), so those sites become router.navigate('/work') with no hooks needed. Inside components use useNavigate() / useLocation() / useMatch().

Phases — incremental, each shippable

PHASE 1

Add dep + scaffold, behavior identical

  • pnpm add react-router (v7 ships DOM bindings in the one package; React 19 compatible).
  • New src/router.tsx (createMemoryRouter + export router) and src/components/RootLayout.tsx (extract shell + overlays out of App.tsx; <main> renders <Outlet/>).
  • main.tsx: render <RouterProvider router={router}/> instead of <App/>.
  • Routes /, /work, /settings map 1:1 to current views. No behavior change.
PHASE 2

Swap nav call sites, delete mainView

  • Replace all showPane/showDashboard/setSettingsOpen/toggleSettings calls per the mapping table (router.navigate outside components, useNavigate inside).
  • Active-state checks → useMatch/useLocation.
  • Remove mainView + those actions from stores/ui.ts. Keep overlay state (palette, help, worktree/clone modals).
PHASE 3

Session restore through the router

  • Persist location.pathname in saveSession(); seed createMemoryRouter(..., { initialEntries: [savedPath] }) so the app reopens on the same surface.
  • Subscribe to router.subscribe (or save on nav) to keep the stored path fresh. Replaces the current loadSession().then(showPane) dance.
PHASE 4 — optional polish

Nested settings routes

  • /settings/:section; section nav uses <NavLink>; useParams().section drives the active/scrolled section instead of the IntersectionObserver activeId state. Index redirects to default-folder.
PHASE 5

Cleanup + verify

  • Delete dead store fields/types. npx tsc --noEmit clean. Smoke-test every nav path + session restore. Optional: bind a key to navigate(-1) (no browser back button in memory history).

Risks & guardrails

  • Memory history only. Never BrowserRouter — there's no URL bar; back/forward come from navigate(-1/+1).
  • Don't route overlays or pane state. Keep palette/help/modals and the pane tree in zustand. URL = surface only. Avoids scope creep.
  • Keep key={activeTab.id} on SplitPane — tab remount is independent of routing.
  • React 19 + react-router v7: supported. Strict-mode double-render is fine with the data router.
  • You have uncommitted WIP across many of these same files (SettingsPage, Header, ProjectTree, etc.) — land or stash that before phase 2 to avoid conflict churn.
